1O que muda em relação ao Windows

A arquitetura é a mesma do guia do sammysan: Sunshine no host, Moonlight no cliente, e os dois só se enxergam pela tailnet — sem port forwarding, sem porta pública. O que muda é tudo que é específico de sistema operacional, e um ponto inverte completamente de sinal.

2Pré-validação do host

Nada aqui altera o sistema. Rode e guarde a saída antes de mexer em qualquer coisa — é o equivalente ao bootstrap-elevated.ps1 do guia do Windows.

bash scripts/bazzite-host-preflight.sh

O script está neste repositório, em scripts/. Ele é somente leitura.

Se preferir à mão, o essencial é:

# imagem e variante
cat /etc/os-release | grep -E '^(PRETTY_NAME|VARIANT_ID)='
rpm-ostree status

# sessão gráfica (precisa ser wayland + KDE para captura via KWin)
echo "$XDG_SESSION_TYPE $XDG_CURRENT_DESKTOP"

# GPU e driver
lspci | grep -iE 'vga|3d'
nvidia-smi --query-gpu=name,driver_version --format=csv,noheader

# o que já existe
tailscale version; systemctl is-enabled tailscaled
flatpak info dev.lizardbyte.app.Sunshine 2>/dev/null || echo "Sunshine ainda não instalado"
systemctl --user is-enabled app-dev.lizardbyte.app.Sunshine 2>/dev/null

# firewall
firewall-cmd --get-default-zone
firewall-cmd --get-active-zones

3Tailscale no host

O binário já está na imagem do Bazzite; o que falta é ligar o serviço. Use a receita do próprio Bazzite, que é só um systemctl enable --now com sudo:

ujust tailscale enable
# equivalente: sudo systemctl enable --now tailscaled.service

Autentique na mesma tailnet do cliente. O --operator evita precisar de sudo para todo comando tailscale depois:

sudo tailscale up --operator="$USER"

O comando imprime um link https://login.tailscale.com/…. Abra, aprove o dispositivo e confirme:

tailscale status
tailscale ip -4          # anote: este é o IP 100.x.x.x do host
tailscale netcheck
O nó antigo do Windows Se este computador é o mesmo sammysan reinstalado, o nó Windows antigo continua na tailnet com o IP 100.78.107.32. O host Bazzite entra como um nó novo, com nome bazzite e IP diferente. Remova o nó antigo no painel (login.tailscale.com/admin/machines) para não confundir os clientes, e use sempre o IP novo daqui para frente. Todo endereço 100.78.107.32 dos documentos do Windows está obsoleto.

Opcional, mas confortável: com MagicDNS ligado na tailnet, o host responde por bazzite e você não precisa decorar o IP.

4Instalar o Sunshine

O caminho suportado no Bazzite para imagem de desktop é o Flatpak, pela receita ujust (a mesma coisa que o Bazzite Portal faz):

ujust setup-sunshine
# escolha: Enable (Flatpak)

A receita faz, nesta ordem:

flatpak install --system -y dev.lizardbyte.app.Sunshine
flatpak run --command=additional-install.sh dev.lizardbyte.app.Sunshine   # pede senha: regras de udev/uinput
systemctl --user enable --now app-dev.lizardbyte.app.Sunshine

O additional-install.sh é o que instala as permissões de entrada (teclado, mouse e controle virtuais via uinput). Sem ele o vídeo até funciona, mas o controle remoto não.

Confirme o serviço e as portas:

systemctl --user status app-dev.lizardbyte.app.Sunshine --no-pager
ss -ltnp | grep -E '47984|47989|47990|48010'
ss -lunp | grep -E '47998|47999|48000'
Quando NÃO usar o Flatpak

O Flatpak não suporta captura por KMS, que é o que o Game Mode (gamescope) das imagens Deck exige. Esta máquina é Kinoite de desktop, então o Flatpak é o certo. Se um dia você quiser transmitir o Game Mode, as alternativas são ujust setup-sunshine enable-brew (pacote experimental) ou camada por COPR — e aí o arquivo de configuração passa a ser ~/.config/sunshine/sunshine.conf, não o caminho do Flatpak.

5Permissões de captura (Wayland/KDE)

Esta etapa não tem equivalente no Windows e é a que mais trava gente. No Wayland, nenhum programa captura a tela sem permissão explícita do compositor.

  1. Na primeira vez que o Sunshine iniciar uma sessão, o KDE pede autorização de compartilhamento de tela — aceite e marque para lembrar.
  2. Confira em Configurações do Sistema → Aplicativos → Permissões de aplicativos (ou Application Permissions) que o Sunshine tem Controle remoto (Remote control) ligado. Sem isso o mouse e o teclado remotos não funcionam.
  3. Na Web UI do Sunshine, em Configuration → Audio/Video, deixe o método de captura em KWin Screencast (ou XDG Portal). X11 e NvFBC não são suportados no Bazzite.
Erro 503 / "Failed to find display"

É a falha clássica do KWin recusando a captura. A correção oficial do Bazzite é a variável de ambiente:

mkdir -p ~/.config/environment.d
echo 'KWIN_WAYLAND_NO_PERMISSION_CHECKS=1' > ~/.config/environment.d/98-kwin-no-permission-checks.conf
# saia da sessão e entre de novo (a variável só vale para sessões novas)

A receita ujust setup-sunshine virtual-monitor → Fix Error 503 escreve exatamente esse arquivo.

Dois monitores

Esta máquina tem duas telas (2560×1440 e 3440×1440). O Sunshine captura uma saída. Escolha qual em Configuration → Audio/Video → Display; caso contrário ele pega a primeira e o cliente recebe a tela errada. Se quiser uma resolução própria para o cliente, sem depender de um monitor físico, use o monitor virtual:

ujust setup-sunshine virtual-monitor   # → Add Virtual Monitor

Isso adiciona uma aplicação "Virtual Monitor" no Sunshine que cria e destrói uma saída KWin por sessão. Só funciona em KWin (Kinoite — é o caso aqui) e exige o método de captura KWin Screencast.

6Credenciais e Web UI local

Faça o primeiro acesso localmente, antes de pensar em acesso remoto:

xdg-open https://localhost:47990      # ou: ujust setup-sunshine portal

O aviso de certificado é esperado — o certificado é autoassinado, igual ao do Windows. Crie o usuário admin com uma senha forte, de 24 caracteres ou mais, gerada na hora. Nunca reutilize a senha do guia antigo, e não grave a senha em arquivo neste repositório.

Se precisar redefinir depois:

systemctl --user stop app-dev.lizardbyte.app.Sunshine
flatpak run --command=sunshine dev.lizardbyte.app.Sunshine --creds admin '<senha>'
systemctl --user start app-dev.lizardbyte.app.Sunshine

Use aspas simples e, de preferência, um histórico de shell desligado (HISTCONTROL=ignorespace + espaço antes do comando).

7Liberar a Web UI pela tailnet

Dois detalhes do Sunshine se repetem aqui exatamente como no Windows, porque são do Sunshine e não do sistema:

1. origin_web_ui_allowed. O padrão lan só aceita faixas privadas (10/8, 172.16/12, 192.168/16). A tailnet usa 100.64.0.0/10 (CGNAT), que não conta como LAN — por isso o acesso pelo IP 100.x é recusado. Precisa de wan.

2. csrf_allowed_origins. Sem a origem exata, o envio do PIN falha com CSRF Protection Error. Foi o que aconteceu no sammysan.

CONF=~/.var/app/dev.lizardbyte.app.Sunshine/config/sunshine/sunshine.conf
cp -a "$CONF" "$CONF.backup-$(date +%Y%m%d-%H%M%S)"

HOST_IP=$(tailscale ip -4)
printf 'origin_web_ui_allowed = wan\nupnp = disabled\ncsrf_allowed_origins = https://%s:47990\n' "$HOST_IP" >> "$CONF"

systemctl --user restart app-dev.lizardbyte.app.Sunshine

Se a chave já existir no arquivo, edite a linha em vez de acrescentar outra. Confira o resultado:

grep -E 'origin_web_ui_allowed|csrf_allowed_origins|upnp' "$CONF"
wan não é "aberto para a internet" wan apenas diz ao Sunshine para não filtrar a origem por faixa de IP. Quem limita o alcance é o firewall (etapa 8) e o fato de não existir port forwarding: a porta continua inalcançável fora da tailnet. Mantenha upnp = disabled para o roteador nunca abrir essas portas sozinho.

8Firewall: restringir à tailnet

Aqui está a diferença real para o Windows. A zona padrão do Bazzite é FedoraWorkstation, e ela contém:

<port protocol="tcp" port="1025-65535"/>
<port protocol="udp" port="1025-65535"/>

Ou seja: todas as portas do Sunshine já estão abertas, em todas as interfaces — inclusive na placa de rede de casa. Nada precisa ser aberto para o Moonlight funcionar pela tailnet. O que vale a pena fazer é o contrário: tirar o Sunshine da LAN.

Não mexa na zona da interface tailscale0 Há um defeito conhecido (tailscale#15968, versões ≥ 1.84; esta máquina roda 1.104.1) em que trocar a zona do tailscale0 no firewalld derruba a interface. A estratégia abaixo nunca toca no tailscale0: ele continua caindo na zona padrão permissiva. Quem fica restrito é a placa cabeada.

Estratégia

  1. tailscale0 → zona padrão FedoraWorkstation (portas altas liberadas ⇒ Sunshine acessível pela tailnet).
  2. enp5s0 (LAN) → zona nova e restrita, sem a faixa 1025‑65535 ⇒ Sunshine inacessível da rede de casa.
bash scripts/bazzite-host-firewall-tailnet.sh            # mostra o que faria (dry-run)
bash scripts/bazzite-host-firewall-tailnet.sh --apply    # aplica
bash scripts/bazzite-host-firewall-tailnet.sh --revert   # volta a LAN para a zona padrão

À mão, é isto:

ZONE=lan-restrito
sudo firewall-cmd --permanent --new-zone="$ZONE"
sudo firewall-cmd --permanent --zone="$ZONE" --add-service=dhcpv6-client
sudo firewall-cmd --permanent --zone="$ZONE" --add-service=mdns
sudo firewall-cmd --reload

# prende a zona na conexão do NetworkManager (sobrevive a reboot e a reconexão)
sudo nmcli connection modify "Conexão cabeada 1" connection.zone "$ZONE"
sudo nmcli connection up "Conexão cabeada 1"

firewall-cmd --get-active-zones

Verifique de outro computador da LAN (fora da tailnet) que a porta fechou, e de um dispositivo da tailnet que ela continua aberta:

# na LAN, deve falhar:
nc -vz <ip-lan-do-bazzite> 47990
# na tailnet, deve conectar:
nc -vz <ip-100.x-do-bazzite> 47990
O que você perde ao restringir a LAN A zona nova bloqueia conexões de entrada da rede local que hoje passam: KDE Connect, Steam Remote Play na LAN, compartilhamentos e qualquer serviço de porta alta. Se usar algum deles, acrescente a porta à zona em vez de desistir da restrição — por exemplo --add-port=1714-1764/udp e --add-port=1714-1764/tcp para o KDE Connect. O script aceita portas extras pela variável EXTRA_PORTS.

Opcional: limitar a um cliente só

Equivalente às regras por IP de origem feitas no Windows. Só vale se você quiser restringir dentro da tailnet:

CLIENTE=100.114.232.6   # IP tailscale do cliente
sudo firewall-cmd --permanent --new-zone=tailnet-sunshine
sudo firewall-cmd --permanent --zone=tailnet-sunshine --add-source="$CLIENTE/32"
sudo firewall-cmd --permanent --zone=tailnet-sunshine \
  --add-port=47984/tcp --add-port=47989/tcp --add-port=47990/tcp --add-port=48010/tcp \
  --add-port=47998/udp --add-port=47999/udp --add-port=48000/udp
sudo firewall-cmd --reload

Zona por source tem precedência sobre zona por interface, e não exige mexer no tailscale0. Para isso valer como restrição, a zona padrão precisa deixar de liberar as portas altas — o que significa também restringir a interface da tailnet, com o risco descrito acima. Prefira controlar isso pelas ACLs da tailnet, que é onde essa decisão pertence no Tailscale.

9Deixar o host pronto sem ninguém na frente

O Sunshine do Bazzite é um serviço de usuário e a captura é do compositor: se ninguém estiver logado na sessão gráfica, não há o que capturar e o serviço nem sobe. No Windows isso não aparecia, porque lá era um serviço de sistema.

Login automático no KDE

sudo mkdir -p /etc/sddm.conf.d
sudo tee /etc/sddm.conf.d/10-autologin.conf >/dev/null <<'EOF'
[Autologin]
User=edi
Session=plasma.desktop
Relogin=false
EOF
Compromisso consciente Login automático significa que quem tiver acesso físico à máquina entra no seu desktop sem senha. É o preço de poder ligar o PC e jogar de longe. Se o computador fica em casa e trancado, costuma valer; se não, prefira deixar a sessão aberta e apenas bloquear a tela — mas atenção: com a tela bloqueada, o KDE pode suspender a captura, então teste antes de confiar.

Não suspender

Em Configurações do Sistema → Energia, deixe "Suspender a sessão" como Nunca no modo ligado na tomada, e desligue o desligamento automático da tela se ele atrapalhar a captura. Pela linha de comando, a trava dura é:

sudo systemctl mask sleep.target suspend.target hibernate.target hybrid-sleep.target
# reverter: sudo systemctl unmask sleep.target suspend.target hibernate.target hybrid-sleep.target

Serviço de usuário ativo cedo

loginctl enable-linger "$USER"     # mantém serviços de usuário vivos
systemctl --user is-enabled app-dev.lizardbyte.app.Sunshine

O linger sozinho não resolve a captura (ela depende da sessão gráfica), mas evita que o serviço morra em transições de sessão.

Jogos

Com o Flatpak, transmita a aplicação Desktop e abra o Steam em Big Picture dentro da sessão, ou cadastre o Steam como aplicação no Sunshine (Applications → Add) com o comando:

steam steam://open/bigpicture

O Game Mode do Bazzite (gamescope) não é transmitido pelo Flatpak — precisaria de captura KMS, do pacote brew/COPR.

10Configurar o cliente Moonlight

O cliente Windows NOTE-LAT-012 já tem Tailscale e Moonlight do guia anterior. Não há nada a instalar — apenas apontar para o host novo:

  1. Confirme que o cliente está na mesma tailnet e que o host bazzite aparece online: tailscale status.
  2. Teste a rota e a porta: 
    tailscale ping <ip-100.x-do-bazzite>
Test-NetConnection <ip-100.x-do-bazzite> -Port 47990
  3. No Moonlight, remova o host antigo (sammysan / 100.78.107.32) e use Add PC com o IP novo.
  4. O Moonlight mostra um PIN. Abra https://<ip-100.x>:47990, aba PIN, informe o código e nomeie o dispositivo.

Para um cliente Linux (inclusive outro Bazzite): flatpak install flathub com.moonlight_stream.Moonlight. Para tablet/celular, o Moonlight das lojas + Tailscale na mesma conta. Em qualquer caso, o pareamento é por PIN e precisa ser refeito por dispositivo.

O pareamento antigo não vale mais

Os certificados de pareamento ficam na instalação do Sunshine. Como esta é uma instalação nova, todo cliente precisa parear de novo, mesmo que o Moonlight ainda liste o host antigo.

11Validação final

  • tailscale status no host mostra a tailnet certa e o host recebeu IP 100.x.x.x.
  • systemctl --user is-active app-dev.lizardbyte.app.Sunshine responde active.
  • ss -ltn mostra 47984, 47989, 47990 e 48010 escutando; ss -lun mostra 47998, 47999 e 48000.
  • Web UI abre em https://localhost:47990 e exige login (não mostra a tela de criação inicial).
  • Do cliente, https://<ip-100.x>:47990 abre e aceita o PIN sem erro de CSRF.
  • Da LAN (fora da tailnet), a porta 47990 não conecta.
  • Moonlight lista as aplicações e inicia a sessão: imagem, áudio, teclado, mouse e controle.
  • Reconexão: fechar e reabrir a sessão no Moonlight funciona sem reiniciar o Sunshine.
  • Depois de um reboot do host, tudo volta sozinho (autologin + serviço + tailscaled).
